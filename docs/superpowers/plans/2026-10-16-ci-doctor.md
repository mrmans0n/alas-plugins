# CI Doctor implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task by task. The user approved implementation in the current session.

**Goal:** Collect truthful bounded GitHub Actions evidence in PR Inbox and send a reviewed brief once to an explicitly selected session.

**Architecture:** Pure normalization and evidence logic, a shared callback process queue and GitHub transport, a detail controller, and native views. Reuse API 15 and the existing local/SSH worktree IDs.

**Tech stack:** TypeScript, plugin SDK, GitHub CLI REST/GraphQL, Node tests and bare JavaScriptCore.

**Spec:** ../specs/2026-10-16-ci-doctor-design.md

## Global constraints

- No merge policy or refresh cadence changes; no background detailed history collection.
- Two processes maximum, structured argv, explicit repository and request identity.
- Fourteen days, 30 summaries per query, five comparison runs per side, five attempts per run, four 25-job pages, four comparison logs.
- Excerpts at most 12 KiB / 100 lines; cache at most eight entries / 256 KiB; brief below 32 KiB UTF-8.
- API 15 cannot preflight terminal/chat kind or atomically bind checkout to sessionSend. Explain host refusals and verification times.

## Review focus

- Fork branch name collisions: remote identity and HEAD verification must determine dispatch eligibility.
- Reruns and force pushes: late replies cannot replace a new selection or reuse a prepared brief.
- Host output truncation and inaccessible logs: preserve partial evidence without reporting a clean history.
- Restart/cache reply races: a restored entry cannot overwrite current evidence or restore a pending send.
- Log instructions, unusual Unicode and Markdown fences: render literal data and keep all host limits.
